# 2026-10-22

- 优化 `start_dev.sh`（开发启动脚本）：
  - 用 `exec` 让子 shell 被 `go run`/`npm` 直接替换，使 `$!` 为真实进程 PID，stop 时能精准整树清理（修复此前 `$!` 为外层子 shell、可能留下孤儿服务占用 8080 的隐患）。
  - 新增 `kill_port` 按端口兜底清理（类 Unix 用 fuser/lsof，Windows 用 netstat+taskkill），stop 后彻底释放 8080/5173。
  - 新增 `need_cmd` 依赖自检（go/npm）、前端 `node_modules` 缺失时自动 `npm install` 兜底、启动后轮询端口给出「已就绪」提示。
  - `restart` 改为 stop 后真正等待进程退出再起；新增 `logs` 命令实时跟踪日志、`help` 命令。
  - 端口仍固定（SERVER_PORT 默认 8080，前端开发服务器 5173、/api 代理目标读 SERVER_PORT），不自动顺延。
  - `.gitignore` 运行时产物规则收紧为 `.dev_*.log*`（覆盖 npm install 日志）。
- 用户要求清空并按当前项目重写 `start_dev.sh`（start/stop/status）：
  - 发现端口不一致：`backend/main.go` 默认 8080，但 `backend/.env` 与 `frontend/vite.config.js` 均为 11118。旧脚本 `export SERVER_PORT="${SERVER_PORT:-8080}"` 硬编码 8080，与 .env 冲突。
  - 新脚本改为解析优先级：shell 环境变量 > `backend/.env` > 8080，并把解析结果导出给前后端子进程，保证两端一致（当前解析为 11118）。
  - 新增 `launch()` 辅助函数：预创建日志文件（消除此前 WSL 下后台重定向 ENOENT）、`setsid` 脱离脚本进程组（Ctrl+C 不误杀后台服务）、`exec` 让 `$!` 为真实进程 PID。
  - 保留 start/stop/restart/status/logs/help；stop 按 PID 整树清理 + 按端口兜底；status 以端口监听为准。
  - 注意：`backend/main.go` 默认值 8080 与 .env 11118 不一致仍未改（脚本导出后 dev 不受影响；如需统一可改 main.go 或 .env.example）。
- 修复 start_dev.sh 在 WSL 下报的「.dev_pids: line 2: 无法创建日志文件:: command not found」：
  - 根因：launch() 日志创建失败时把「无法创建日志文件」错误信息经 `$(...)` 捕获进了 FRONTEND_PID，污染 .dev_pids；status 用 `source` 读取时把那行当命令执行。且 .dev_frontend.log 被上次残留 vite 进程占用导致截断失败。
  - 修复：① 读取 PID 改用 grep（read_pid，只认纯数字行，绝不 source，免疫污染文件）；② do_start 启动前先清理残留进程/端口（kill_port）再建日志；③ launch 日志创建失败时降级 /dev/null 但服务照常启动，且 PID 校验必须为纯数字否则报错退出；④ Unix 分支 kill_tree 加进程组杀（setsid 使 PGID=PID）、kill_port 加 ss 兜底。
- 环境差异注意：用户在 WSL（/mnt/d，zsh），本沙箱是 Git Bash（MINGW64）。WSL 启动的进程从 Git Bash 无法按 PID 杀（PID 不互通），且沙箱禁用 wsl.exe。当前 11118 有一个 WSL 残留后端进程，需用户在 WSL 里跑 `./start_dev.sh stop`（或 start，端口清理会自动杀）清掉。
